# Hermes PR Workflow Skill

## Purpose

Automate the full GitHub PR lifecycle inside Hermes Agent, inspired by the NousResearch demo (Neotron Labs livestream). This skill covers:

1. Finding and reviewing PRs
2. Cherry-picking commits
3. Merging via rebase
4. Salvaging the workflow as a reusable skill

## Prerequisites

- Hermes Agent installed with `github` toolset enabled
- `GITHUB_TOKEN` in profile `.env` (masked by OpenShell policy if sandboxed)
- Git configured with user name/email

## Workflow Steps

### 1. Review a PR

```bash
# Hermes Agent command sequence
hermes chat -q "Find PR #1 in repo OWNER/REPO and review it"
```

Expected behavior:
- Connects to GitHub API
- Fetches PR details, diff, and comments
- Analyzes code changes
- Produces review summary with suggestions

### 2. Cherry-pick Commits

```bash
hermes chat -q "Cherry-pick the commits from PR #1 into branch main"
```

Expected behavior:
- Identifies commits in PR
- Creates new branch if needed
- Applies commits cleanly or reports conflicts

### 3. Merge via Rebase

```bash
hermes chat -q "Merge PR #1 using rebase and close the PR"
```

Expected behavior:
- Rebase merges commits onto target branch
- Closes PR with merge commit
- Updates local branch

### 4. Salvage Workflow as Skill

```bash
hermes chat -q "Salvage this PR review workflow as a reusable skill named pr-review-skill"
```

Expected behavior:
- Analyzes the session history
- Extracts the workflow pattern
- Creates `pr-review-skill/SKILL.md` in skills directory
- Registers skill for future reuse

## PMOVES-Specific Adaptations

### Multi-User Support (Alice/Bob Pattern)

```yaml
# In hermes-agent.room.control.json
multi_user:
  enabled: true
  user_isolation:
    skills: per_user
    memory: per_user
    sandbox: per_user
```

Each user gets their own:
- Skill namespace (`alice/pr-review-skill` vs `bob/pr-review-skill`)
- Memory store (workflows learned per user)
- Sandbox (isolated GitHub tokens)

### Environment Variable Masking

```bash
# Inside sandbox, tokens are masked
echo $GITHUB_TOKEN
# Output: ***MASKED***

# At egress, Hermes substitutes the real token
# when calling GitHub API
```

### Policy Gates

```yaml
sandbox_policy:
  egress_rules:
    - service: github
      allowed: true
      scope: api_only
```

Forbidden: direct `git push` without policy approval.
Allowed: GitHub API calls for PR review/merge.

## Atomic Commits & Targeted PRs

Every PR created by Hermes Agent MUST follow PMOVES atomic commit rules:

### Commit Message Format
```
<type>(<scope>): <subject>

<body>
```

**Types:** `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`

**Scopes:** `hermes-agent`, `hermes-room`, `hermes-profile`, `hermes-skill`, `hermes-tac`, `hermes-registry`, `hermes-docs`, `hermes-research`

### Rules
1. **One concern per commit** -- do not bundle unrelated changes
2. **< 400 lines per PR** -- if bigger, split into stacked PRs
3. **Reviewable in < 30 min** -- focused, single-feature PRs
4. **CHIT-signed** -- every PR carries CHIT attestation
5. **Hardware changes require live scan** -- update `system-specs.json` and `glances.conf`

### Example: Hardware Correction PR
```bash
# 1. Live scan
python -c "import psutil; ..."
nvidia-smi --query-gpu=name,memory.total --format=csv

# 2. Atomic commit
feat(hermes-profile): correct Z890 GPU spec from RTX 3090 Ti to GTX 1650

- Live system scan confirmed GTX 1650 4GB
- Updated z890.yaml, z890-glances.conf
- Updated HERMES_AGENT_INTEGRATION.md model routing matrix
- Updated TAC tree hardware metadata
```

### PR Template (auto-generated by skill)

## Troubleshooting

| Issue | Cause | Fix |
|-------|-------|-----|
| GitHub API 401 | Token expired/masked | Re-auth: `hermes auth add github` |
| Merge conflict | Divergent branches | Hermes will report conflicts; resolve manually |
| Skill not found | Per-user isolation | Check user's skill namespace |
| Policy blocked | Egress rule | Verify `sandbox_policy.egress_rules` |
