# Handoff: gw-priority + PMOVES_NETWORKS in compose (network-awareness, item 3)

**Status:** apply-ready. **Known-Road-gated** (editing `docker-compose*.yml` trips the guard):
```
KNOWN_ROAD=compose:handoff:COMPOSE_GW_PRIORITY_NETWORK_AWARENESS.md
```
Edit the **SOURCE** (`pmoves/docker-compose.yml`) only — the `docker-compose.*.yml` overlays are
GENERATED by `scripts/split_compose.py`. After editing, **regenerate + drift-check**:
```
make -C pmoves compose-split          # regenerate overlays from the source
make -C pmoves compose-split-check    # drift gate — must pass
```
Prereq verified: Docker Compose **v5.3.0** supports `gw_priority` (needs ≥ v2.30 / Engine 28).

## Why
Implements `HYBRID_TOPOLOGY_NETWORK_AWARENESS.md` §6 and the grounded Flute→TTS fix:
1. **`gw_priority`** on `pmoves_external` makes it the **default route** for multi-homed
   services, so `host.docker.internal` / internet is reachable. This is the documented
   root cause of Flute→TTS "network unreachable" (default route landed on an internal tier).
2. **`PMOVES_NETWORKS`** env lets each service self-report its Docker tiers via the extended
   `TopologyContext` (PR #2183) → the new `/topology` endpoints (media-audio/-video) light up.

## The edit (per multi-homed service on `pmoves_external`)
Convert the `networks:` **list** to the **map** form + set `gw_priority`, and add the env.

**media-video** (`pmoves/docker-compose.yml` ~line 1982 env, ~2006 networks):
```yaml
    environment:
    - ...existing...
    - DETECTION_ENGINE=${DETECTION_ENGINE:-detr}     # detr (Apache, ship) | yolo (private/Jetson)
    - PMOVES_NETWORKS=pmoves_app,pmoves_bus,pmoves_external
    networks:
      pmoves_app: {}
      pmoves_bus: {}
      pmoves_external:
        gw_priority: 100      # default route: host/internet (model downloads)
```
**media-audio** (~line 59 block): same, `PMOVES_NETWORKS=pmoves_app,pmoves_bus,pmoves_external` +
the `networks:` map with `gw_priority: 100` on `pmoves_external`.

**flute-gateway** (the known-broken case, docker-compose.media.yml source block): same map +
`gw_priority: 100` on `pmoves_external` + `PMOVES_NETWORKS=pmoves_api,pmoves_app,pmoves_bus,pmoves_external`.
This is the direct fix for the Flute→native-Ultimate-TTS reachability wall.

Roll out to the rest of the multi-homed-on-`pmoves_external` fleet the same way (grep
`- pmoves_external` in the source, convert each).

## Optional Tailscale/Pinokio env (per §4, where applicable)
For services fronted by Tailscale Serve, add `TAILSCALE_SERVE_URL` / `TS_NODE` / `TAILNET` /
`TS_TAGS`. For services that call native Pinokio apps, add `PINOKIO_ENDPOINTS` (json map),
e.g. flute-gateway: `PINOKIO_ENDPOINTS={"ultimate-tts":"http://host.docker.internal:7860"}`.
