# MiniMax API Key Setup

**Safe workflow for activating MiniMax models in PMOVES.AI via TensorZero.**

MiniMax-M2.7 (1M context) and MiniMax-M2.1 (100K context) are pre-configured
in TensorZero. They activate automatically when the API key reaches the env pipeline.

---

## Quick Start (GitHub Secrets → CHIT → TensorZero)

```bash
# 1. Add key to GitHub Secrets (cloud source of truth)
gh secret set MINIMAX_API_KEY --repo POWERFULMOVES/PMOVES.AI

# 2. Sync secrets through CHIT pipeline to local tier files
make -C pmoves secrets-funnel

# 3. Restart TensorZero to load the new key
make -C pmoves up-tensorzero

# 4. Verify routing
curl -X POST http://localhost:3030/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "minimax-m2.7", "messages": [{"role": "user", "content": "Hello from PMOVES"}]}'
```

## Alternative: Interactive Bootstrap

If running first-time setup or prefer interactive prompts:

```bash
make -C pmoves env-setup       # Prompts for missing keys (MINIMAX_API_KEY included)
make -C pmoves brand-defaults  # Apply branded defaults
make -C pmoves up-tensorzero   # Restart gateway
```

The `env-setup` target reads `bootstrap/registry.json` and prompts for any key
with a `"prompt"` field. MINIMAX_API_KEY is registered as optional + sensitive,
so it uses masked input and skips gracefully if left empty.

## How It Works

```
GitHub Secrets (you add key here via gh secret set)
    |
    v
sync-secrets-local.yml (GH Actions → CHIT bundle)
    |
    v
make secrets-funnel (CHIT decode → tier file distribution)
    |
    v
Docker Compose via Make targets (--env-file injection)
    |
    v
tensorzero-gateway reads $MINIMAX_API_KEY from environment
    |
    v
Models minimax-m2.7 and minimax-m2.1 route to MiniMax API
```

## What NOT to Do

- **NEVER** edit `env.tier-llm`, `env.shared`, or any `env.tier-*` file directly
- **NEVER** use `echo >> env.tier-llm` or similar shell writes to env files
- **NEVER** use `docker compose up` directly (bypasses `--env-file` injection)
- **NEVER** hardcode the key in any config, TOML, or YAML file

Env files are in `zeroAccessPaths` — damage control hooks block all access.
They are auto-generated by the secrets pipeline. The only entry points are:
1. `gh secret set` (cloud) → `make secrets-funnel` (local)
2. `make env-setup` (interactive prompt)

## Cascade Behavior

When the key is present, TensorZero routes to MiniMax based on the
provider cascade in `tools/models/minimax_provider_cascade.yaml`:

| Model | Context | Cascade Priority | Fallback |
|-------|---------|------------------|----------|
| minimax-m2.7 | 1M tokens | High | qwen3.5-27b |
| minimax-m2.1 | 100K tokens | Medium | glm-4 |

When the key is absent, TensorZero silently skips MiniMax and falls
through to the next provider in the cascade. No errors, no disruption.

## NATS Events

The provider cascade emits events when MiniMax activates or deactivates:

| Subject | When |
|---------|------|
| `claw.provider.activated.v1` | Key present, cascade validates successfully |
| `claw.provider.deactivated.v1` | Key removed or provider fails validation |

BoTZ gateway subscribes to these events and updates its routing table.
