What is a CGP packet?

A CGP (Consciousness Geometry Packet) is how CHIT encodes meaning as geometry instead of token streams. Think of it as a weather map for ideas: a super_node is a continent, a constellation is a weather system, the anchor is the wind direction, the spectrum is the pressure distribution, and the points are weather stations reporting what they see.

02 · From text to geometry

      
Encoding: how words become shapes

      

        The encoding pipeline: text → embed → harvest (CHR) → measure (spectrum) → package (CGP).
        Below is the actual CGP for the selected scenario, with live spectrum visualization.
      


      

        
1Raw input → embedding

        
The source text is split into units (sentences, audio segments, economic records). Each unit is embedded into a vector using a sentence-transformer model.

        

      


      

        
2CHR harvest → anchor discovery

        
The CHR (Constellation Harvest Regularization) algorithm discovers K anchor directions in the embedding space. Each anchor defines a constellation — a cluster of related units.

        

      


      

        
3Spectrum measurement

        
For each constellation, all points are projected onto the anchor and binned into a histogram — the spectrum. This is the "energy distribution" of meaning along that direction.

        

      


      

        
4The assembled CGP packet

        

      

    


    
    

      
03 · Cryptographic signing

      
Sign the CGP with HMAC-SHA256

      

        CHIT signs every CGP packet with HMAC-SHA256. The signature is computed over the canonical JSON
        (sorted keys, no whitespace) minus the sig field itself. This runs
        real WebCrypto in your browser — not a simulation.

04 · NATS JetStream

      
The Geometry Bus

      

        Signed CGP packets travel the Geometry Bus — NATS JetStream with 30-day replay.
        Producers publish, consumers subscribe, ShapeStore persists. Below is the actual
        publish flow with the real NATS subjects.
      


      

        
Publish flow

        

          
Producer
tokenism.cgp.ready.v1

GEOMETRY_CGP stream

          →

          →
          
Consumers
tokenism.cgp.weekly.v1

        


        
The ShapeStore computes a Shape ID (truncated SHA-256 of the canonical CGP) and writes it to disk + Supabase. This is the persistent record that future decode/verify calls reference.

Shape ID computation

            
The canonical JSON (sorted keys, no whitespace, sig stripped) is SHA-256 hashed. The first 16 hex chars become the Shape ID.

            
            

          

        

      

    


    
    

      
05 · Proof of integrity

      
Verify & tamper

      

        Anyone can verify a CGP's signature without trusting the producer. The verification re-canonicalizes
        the JSON (stripping sig), re-derives the key, and checks the HMAC. If even one byte changes,
        verification fails. Try it.
